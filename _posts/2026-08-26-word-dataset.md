# JYP-Word : 하루 20단어 학습 사이트

전참시 JYP 편에서 JYP가 꾸준히 자기 관리하는 모습이 멋있어 보였다. 특히 하루에 영어 단어 20개를 외운다는 이야기를 듣고, **매일 20개씩이라면 부담 없이 꾸준히 공부할 수 있겠다**는 생각이 들었다.

그래서 하루마다 영어 단어 20개와 예문을 보여주는 학습 사이트, **JYP-Word**를 만들어 보기로 했다.

## 1. 영단어 목록

프로젝트를 본격적으로 시작하며 가장 먼저 한 일은 학습할 영단어 목록을 찾는 일이었다. 다른 영단어 앱이 사용하는 데이터셋도 찾아봤지만, 바로 활용할 수 있는 자료는 찾기 어려웠다.

그러다 `교육부 선정 영단어 3000개`와 [Words-CEFR-Dataset](https://github.com/Maximax67/Words-CEFR-Dataset/)을 발견했다. 
검등된 영단어라고 생각되었고, 학습 난이도를 나누기에도 적합해 보였다.

하지만 이 데이터셋에는 영어 단어 목록만 있어, `한글 뜻`, `영어 예문`, `예문의 한글 해석` 데이터를 추가해서 데이터셋을 만들고자 했다.

→ 단어 데이터셋 자동화 프로그램부터 생성하고자 했다.
→ 아래의 내용은 전부 데이터셋 자동화 프로그램을 만들기로 시도한 방법이다.

## 2. 번역기 API (Papago API, Google 번역기 API)

영어 단어 목록은 이미 있으니, 번역 API를 사용하면 한글 뜻을 쉽게 채울 수 있을 것이라고 생각했다.

### Papago API

Papago API는 비교적 정확한 한글 뜻을 제공했다. 하지만 2024년 2월 29일부터 무료 API 제공이 중단되어, 사용하려면 비용이 필요했다.

유료로 파파고 API를 사용하기에는 거부감이 있어, 무료로 만들둘 수 있는 다른 대안을 찾고자 했다.

### Google 번역 API

Google 번역 API로도 한글 뜻을 가져올 수 있었다. 자동으로 데이터를 채울 수 있다는 가능성은 확인했다.

하지만 번역 API는 대체로 단어의 대표 번역 하나만 반환한다. 예를 들어 `bank`에는 아래와 같은 뜻이 있다.

- 은행
- 예금하다
- 강둑

단어 학습 사이트라면 하나의 번역만 보여주기보다, 여러 의미를 함께 보여주는 편이 좋다고 생각했다.

→ **Papago API는 비용 문제료 사용을 하지 않았다.**  
→ **번역기 API는 여러 뜻을 제공받기 어려워, 사전 데이터와 예문 데이터를 따로 찾아보기로 했다.**

## 3. Wiktionary + Tatoeba

단어의 여러 뜻과 다양한 예문을 얻기 위해 이것저것 찾다가 `Wiktionary`와 `Tatoeba`를 발견했다.

| 서비스 | 제공사항            |
| --- |-----------------|
| Wiktionary | 단어의 여러 뜻과 음성 수집 |
| Tatoeba | 영어 예문 수집        |

두 서비스 모두 API를 제공했고, Tatoeba는 예문 JSONL 파일도 무료로 제공했다. 역할을 나누면 자동화가 가능해 보였다.

### Wiktionary의 문제

전체 데이터 셋을 만들기 전에 랜덤으로 100개정도 샘플링해서 데이터셋을 먼저 만들고 검토를 진행해봤다.
우선 Wiktionary를 통해 단어 뜻을 채운 뒤 확인해 보니 `contractee`처럼 데이터가 없거나 정보가 부족한 단어가 상당히 많았다.

### Tatoeba의 문제

예문은 많았지만, 학습용으로 적절한 문장인지 자동으로 판단하기 어려웠다.

- 문맥이 부족한 문장
- 지나치게 짧거나 어색한 문장
- 단어의 뜻과 잘 맞지 않는 문장

→ **실제로 데이테를 채워보니 모든 단어에 대한 정보가 없었고, 품질을 사람이 전부 검토해야만 했다.**

## 4. OpenSubtitles

`OpenSubtitles`는 영화와 드라마 자막을 기반으로 하므로 자연스러운 실제 영어 문장이 매우 많았다. 일상적인 표현도 풍부해 예문 후보를 찾기에는 매력적인 데이터였다.

하지만 서비스에 활용하려면 저작권과 라이선스, 그리고 데이터 사용 범위를 명확히 확인해야 했다. 또는 영화사에 일일히 사용허락은 받아야 했다.

→ **라이선스 문제로 OpenSubtitles는 사용하지 않기로 결정.**

## 5. 네이버 사전 !! (보물창고 발견)

데이터를 어떻게 채우고 정제할지 고민하다가 네이버 사전을 확인했다. 이곳에는 내가 원하던 정보가 거의 모두 있었다.

- 다양한 단어 뜻
- 영어 예문
- 예문의 한글 해석

마치 보물창고를 찾은 기분이었다. API만 활용할 수 있다면 가장 좋은 방법이라고 생각했다.

하지만 네이버 사전 API는 이미 지원이 중단된 상태였다.

→ **다른 사전 API가 있는지 더 조사해 보기로 했다.**

## 6. 사전 API 조사

`Daum`, `Google`을 포함한 다른 사전 API도 찾아봤다. 하지만 대부분은 지원이 중단되었거나 API를 제공하지 않았고, 제공하더라도 유료 서비스인 경우가 많았다.

**결과:** 무료이면서 안정적으로 사용할 수 있는 사전 API를 찾지 못했다.

→ **Sample 데이터셋을 수기로 작성하고 기능먼저 작업하자.**

## 7. 테스트 데이터 수기 생성

처음에는 모든 단어 데이터를 자동으로 만들려고 했다. 하지만 조사할수록 데이터 수집, 라이선스 확인, 예문 품질 검수 등 생각보다 큰 작업이라는고 생각되어

데이터셋 문제만 붙잡고 있으면 사이트의 다른 기능까지 계속 늦어질 것 같았다. 그래서 방향을 바꿨다.

> 우선 약 100개의 단어를 직접 정리하고, 그 데이터로 사이트의 다른 기능부터 만들기로 했다.
{: .prompt-tip }

영단어 자동화 데이터셋은 추후 기능 완성 이후 도전과제로 남겨두고, 지금은 먼저 사용자가 하루 20개 단어를 보고 공부할 수 있는 경험을 만드는 일이 더 중요하다고 판단했다.
